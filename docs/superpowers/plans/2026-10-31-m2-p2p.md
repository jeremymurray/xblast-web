# M2 — Two-player P2P over WebRTC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `web/net_stub.c` with a real `socket.h` implementation backed by two WebRTC DataChannels and Trystero room discovery, and add a clean HTML host/join lobby that two browsers can play through.

**Architecture:** The page owns a Trystero room. `web/net.js` joins it, creates a reliable-ordered `xb.ctl` channel and an unreliable-unordered `xb.act` channel on every peer connection, and exposes an fd-based queue API. `web/net_web.c` implements `engine/socket.h` on that API, including synthetic fds, listen/accept, connect waiting, byte queues, half-close and EOF. Guarded `#ifdef __EMSCRIPTEN__` hooks in the engine's menus jump straight into the host's game setup or the guest's join setup, and the HTML lobby owns the room code and status.

**Tech Stack:** C (XBlast TNT 2.10.4), Emscripten + Asyncify, WebRTC DataChannels, Trystero 0.26.0 (Nostr strategy), `@trystero-p2p/core` 0.26.0, `@noble/secp256k1` 3.2.0, vanilla HTML/CSS/JS, Python CDP test harness (no third-party test deps).

**Spec:** `docs/superpowers/specs/2026-10-31-m2-p2p-design.md`

## Review Focus

These are the failure modes most likely to bite a player, and each is pinned by a test in the task named:

1. **The match dies at start.** `Server_SendStart()` calls `Server_StopListen()`; closing the listen socket must not close accepted peer channels. Pinned in Task 3 (shim: close listen, accepted stream still carries bytes) and Task 4 (netplay reaches the playfield and exchanges `act` traffic).
2. **Guest connects while the host is still choosing players.** The host joins the room at Host-click, so the guest must see a host hello and wait, not time out. Pinned in Task 4 (guest starts before the host presses Continue).
3. **Half-close loses queued data.** Data sent before `Socket_ShutdownWrite` must arrive before EOF, and closing must not leave the room. Pinned in Task 3 (shim: send, shutdown, peer drains data then sees EOF).
4. **One peer leaving kills the host's other peers.** Closing an accepted stream or a client stream must only affect that peer; the room and other accepted channels stay. Pinned in Task 2 (JS: host + two clients, close one, the other still sends).
5. **Wrong room hangs forever.** A guest with no host must fail within the configured timeout and stay cancellable. Pinned in Task 2 (JS: wrong room with a 500 ms timeout fails promptly).
