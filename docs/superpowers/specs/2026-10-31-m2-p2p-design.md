# M2 — Two-player P2P over WebRTC

Date: 2026-10-31
Status: design, awaiting approval
Milestone: M2 (release target 0.3.0)
Supersedes: the `web/net_stub.c` placeholder

## 1. Context

`xblast-web` is the XBlast TNT 2.10.4 C engine compiled to WebAssembly with
Emscripten. M0 and M1 are done: the engine boots in a browser, single-player
works, the SDL 2 backend lives in `web/compat/` and `web/sdl_web.c`, and the
build is a static site. Networking is currently a stub: `web/net_stub.c`
implements `engine/socket.h` with calls that always fail.

The engine already has a complete, host-authoritative network model:

- `engine/socket.h` is the only network seam. `engine/net_socket.c` wraps it and
  `engine/com_base.c` multiplexes live sockets by file descriptor.
- Control traffic is a reliable byte stream of framed telegrams (`com_stream.c`,
  `net_tele.c`). The host listens, accepts clients, and sends the game config,
  player configs, level data, chat and the random seed over it.
- Per-frame actions are datagrams (`com_dgram.c`, `net_dgram.c`), ~20 Hz,
  at most 255 bytes each. The host inserts all players' actions and clients
  block until the host's frame arrives.
- The engine has no lobby; it expects a host name/port to connect to and a
  listening port. That is the gap M2 fills.

`engine/sdl_socket.c` is the native implementation and is not compiled for the
web build. `web/net_stub.c` is the web slot; M2 replaces it.

## 2. Intent

Two people open the same static page, type the same short room code, one hosts,
one joins, and they play a normal XBlast match. No backend, no account, no
game server. The engine's netcode and game logic stay as they are.

## 3. Goals

1. A real `socket.h` implementation for the web, backed by two WebRTC
   DataChannels per peer:
   - reliable, ordered for the engine's stream/control protocol;
   - unreliable, unordered for action datagrams.
2. Serverless room discovery with Trystero. A host and a guest who enter the
   same room code find each other through public Nostr relays and connect
   directly.
3. A small, clean HTML lobby. It owns the room code, Host/Join intent, progress
   and errors. It is not a second game UI.
4. Reuse the engine's existing player/level setup menus for the host and the
   guest. Skip only the engine's obsolete network-plumbing screens
   (Setup Server, Connect to Server, LAN/central search).
5. Prove it with two headless Chrome instances, and leave a manual two-browser
   procedure.
6. Keep all engine changes `#ifdef __EMSCRIPTEN__`, small, and navigational.
   No game logic or netcode changes.

## 4. Non-goals

- No TURN server in M2. Trystero's default STUN is used. A peer pair that
  cannot connect directly gets a clear error; TURN is M4.
- No host migration, reconnection, or resume.
- No chat UI. The engine's chat transport still works over the reliable channel,
  but the web lobby does not add chat.
- No 6-player tuning or verification. The design supports multiple peers, but
  M2 is accepted on two players.
- No desync state hash. The engine's deterministic seed still travels over the
  reliable channel; a per-round hash is M3.
- No rollback or prediction.
- No change to `socket.h`, `com_*`, `net_*`, `game_*`, or `server.c`/`client.c`
  behaviour.

## 5. Anti-goals

- A hidden background relay or a central server in the default path.
- JS input injection to drive the engine's menus.
- Rewriting the engine's menu or network stack in JS.
- Silently hanging when the room or peer cannot connect.
- Shipping a room code that is really a TCP port number.

## 6. Constraints and decisions already made

- Base: XBlast TNT 2.10.4 + Debian patches, vendored in `engine/`.
- Emscripten + Asyncify. The engine's blocking loops already work by yielding
  through `emscripten_sleep`.
- Trystero is the chosen signalling layer. MIT licensed, GPL-compatible.
- WebRTC star: host browser is the authoritative game server.
- Two DataChannels, reliable-ordered control and unreliable-unordered actions.
- Static hosting only. The vendored Trystero bundle is served from the same
  origin; no CDN or runtime download.
- Whole work stays GPL-2.0-or-later with complete source.
- Attribution: every commit ends with
  `Assisted-by: DeepSeek V4.1 Flash Free (opencode/deepseek-v4.1-flash-free)`.

## 7. Approaches considered

**A. Overlay collects the code, engine menus do the rest (zero engine diff).**
The host types the code into Setup Server's *Name:* field, the guest types it
into *Hostname:*, and *TCP-Port* is ignored. Works, but the labels lie and every
player walks two plumbing screens. Rejected for the experience.

**B. Overlay + guarded engine entry hooks (chosen).**
A real HTML lobby owns the room code and Host/Join intent. Guarded
`#ifdef __EMSCRIPTEN__` hooks in `menu.c` / `menu_game.c` / `menu_network.c`
open the host's game-setup menu or the guest's join-setup menu directly, and
route Continue/Connect to the web transport. The engine's game-facing menus are
kept. Cost: roughly 60–100 guarded lines, no netcode changes. This is the
smallest change that produces a clean flow.

**C. Full web lobby, engine only runs matches.**
Reimplement player/level/team setup in HTML. Prettier long-term, but duplicates
engine config semantics for no M2 benefit. Deferred to M3/M4.

## 8. Architecture

### 8.1 Layer map

```
HTML lobby (index.html)
  └─ sets globalThis.xbConfig = {mode, room}
  └─ loads xblast.js, shows room/status bar
C engine (unchanged netcode)
  └─ socket.h calls
web/net_web.c  (replaces net_stub.c)
  └─ EM_JS calls into XBNet
web/net.js
  └─ Trystero room + two negotiated DataChannels per peer
  └─ byte queues, fd table, hello/eof framing
Trystero (vendored ESM, Nostr relay discovery)
  └─ RTCPeerConnection per room peer
```

All state that needs to survive an Asyncify suspension lives in JS. C never
calls into JS while the engine is running; JS only enqueues. C pulls when it
wakes.

### 8.2 Rooms and peers

- Trystero app id: `xblast-tnt-web-v1`.
- Lobby room code: lowercase words/digits with single dashes, 1–32 chars.
  Default generated as `word-word-NN` from a small word list. The user may edit
  it.
- Trystero room id: `xblast-tnt-<code>`.
- One active room per page.
- Host and guest both join the same room. Trystero connects every peer in the
  room, so with three or more browsers the topology is a mesh; the engine only
  uses the host-guest edges. Clients ignore other clients.
- Peer identity is Trystero's `selfId`. It is used directly as the synthetic
  host name the engine sees, so the engine's NAT detection compares equal
  strings and stays in connected mode.
- The host is the peer that announced `role=host`. There is exactly one host in
  a room; a second host is ignored by clients.

**Room lifecycle is page-owned, not socket-owned.** This is deliberate and
matters:

- The HTML lobby calls `XBNet.enter(mode, room)` on Host/Join click, before
  `xblast.js` is loaded. Trystero joins the room and starts creating channels
  immediately.
- `Socket_Listen` and `Socket_Connect` only attach an engine fd to the existing
  session. They never join or leave the room.
- `Socket_Close` only detaches an fd (and, for an accepted host stream, closes
  that peer's channels). It never leaves the room.
- The room is left only by the HTML **Leave** action (which calls
  `XBNet.leave()` and reloads), by `Socket_Finish` on engine shutdown, or by the
  browser closing the tab.
- The room therefore survives `Server_StopListen()` at match start and
  `Client_Disconnect()` at match end. Closing the listen socket means “stop
  accepting new peers”, not “close the party”.
- Because the host joins at Host-click, its ctl hello is already visible while
  it is still configuring players and levels. A guest that reaches Connect
  during that window sees the host and proceeds to the wait screen instead of
  timing out. The guest's `Socket_Connect` timeout therefore means “no host in
  this room”, not “host is slow”.
- If the host aborts before a match, `ButtonServerDisconnect` disconnects the
  guests, their accepted streams close, and guests see EOF. The room remains
  joined until Leave/reload; M2 does not attempt an in-place rematch.

### 8.3 Channel protocol

Both sides create two **negotiated** DataChannels on the `RTCPeerConnection`
returned by `room.getPeers()[peerId]`:

| label | id | options |
|---|---|---|
| `xb.ctl` | 42 | `ordered: true` |
| `xb.act` | 43 | `ordered: false, maxRetransmits: 0` |

Negotiated channels avoid `ondatachannel` timing races and do not trigger
renegotiation. Trystero's own channel uses a dynamic id, normally 0, so 42/43
do not collide. This was verified in a two-headless-Chrome spike: both
channels opened and carried bytes.

`xb.ctl` messages are framed with a one-byte type:

- `1` hello: payload `[version=1, role]`, role `1=host`, `2=client`
- `2` data: engine stream bytes
- `3` eof: writer half-close
- `4` close: writer is going away

Each side sends its hello when its `xb.ctl` channel opens. A peer is a valid
counterpart only if the hello role is the opposite of the local role and the
version matches. Invalid counterparts are ignored; their channels may be
closed. `xb.act` carries raw datagram bytes and has no hello; it is only used
after the ctl hello has established the peer's role.

### 8.4 Socket shim (`web/net_web.c`)

`web/net_web.c` replaces `web/net_stub.c` and implements the whole of
`engine/socket.h` on top of `XBNet`. Synthetic fds start at 1000 and are unique
across all live sockets, because `ComFind` compares them.

Mapping:

| socket.h | web behaviour |
|---|---|
| `Socket_Open` | allocate fd, `XBNet.open(fd, stream|dgram)` |
| `Socket_SetAddressInet` | record host/port; host is a room code for a client stream, a peer id for a dgram |
| `Socket_Listen` | `XBNet.listen(fd)`; attaches to the room the lobby already joined. A direct engine call without a lobby session falls back to joining `XBWeb_RoomCode()`. |
| `Socket_Accept` | pop the next pending client peer, bind a new fd to it |
| `Socket_Connect` (stream) | `XBNet.connect(fd, room)`, then poll state in 50 ms slices for up to 20 s; cancellable. Success means a host hello is present, not that the host has started the match. |
| `Socket_Connect` (dgram) | `XBNet.attachPeer(fd, host)`; no wait |
| `Socket_Send` (stream) | `XBNet.send`; full buffer accepted, `WOULD_BLOCK` if the ctl channel is not open or its `bufferedAmount` is high |
| `Socket_Send` (dgram) | `XBNet.send`; `WOULD_BLOCK` if the act channel is not open (the engine treats that as a dropped datagram) |
| `Socket_Receive` (stream) | copy queued bytes; `0` when the peer's eof/close was seen and the queue is empty; `WOULD_BLOCK` otherwise |
| `Socket_Receive` (dgram) | one queued datagram per call; `WOULD_BLOCK` if empty |
| `Socket_ShutdownWrite` | send ctl `eof`; keep the channel open for reading |
| `Socket_Close` | release the fd; close per-peer channels where the role requires it (below); never leave the room |
| `Socket_HostName/Port` | local name = `selfId`, remote name = peer id, port = 16168 |
| `Socket_GetInterfaces` | none; LAN discovery is unavailable on web |
| `Socket_SetBroadcast/SetReuse` | true no-ops |
| `Socket_SendTo/ReceiveFrom` | no-op/unsupported for M2 (LAN paths are off) |

Close semantics:

- Guest closes its stream socket → close that peer's channels; do **not** leave
  the room. The host sees EOF on the accepted stream. This is what
  `Client_Disconnect()` does at the end of every match.
- Host closes its listen socket → stop accepting; close channels for peers that
  were still pending (never accepted); keep the room and every accepted peer's
  channels. This is what `Server_StopListen()` does at match start.
- Host closes an accepted stream socket → close that peer's two channels only;
  the room and other peers stay.
- Dgram close → unbind the fd from its peer; do not close the channels.
- Only `XBNet.leave()` / `Socket_Finish` leave the room.

This split is why the design does not put room ownership in the listen fd:
the engine deliberately closes the listen socket before a match and tears down
client streams at the end of a match, while the peer channels must stay alive
for the match itself.

`SelectSockets`:

- Keep a global list of live sockets with read/write registration flags.
- If no socket is registered, sleep the whole timeout (or 50 ms when the
  timeout is NULL), preserving current solo behaviour.
- If any socket is registered, poll in 5 ms slices up to the timeout, dispatch
  `CommReadable`/`CommWriteable` for ready fds, and return early when something
  was dispatched.
- Dispatch from a snapshot of fds; skip fds whose comm disappeared during the
  dispatch.

### 8.5 JS transport (`web/net.js`)

A module, loaded before `xblast.js`. It imports
`{joinRoom, selfId}` from the vendored `@trystero-p2p/nostr`.

Per session:

```
session = {
  room, role, roomObj,
  peers: Map(peerId -> { pc, ctl, act, ctlOpen, actOpen, role, version,
                         ctlQueue, actQueue, eof, closed, fds }),
  pending: [peerId],          // host: clients that have said hello
  listenFd, connectFd, connectPeer,
  error, cancelled, startedAt,
  stats: { ctlTx, ctlRx, actTx, actRx, ... }
}
```

Key operations:

- `enter(mode, room)`: called by the lobby before the engine loads. Leave any
  previous room; `joinRoom(...)`; install `onPeerJoin`, `onPeerLeave`,
  `onJoinError`. For peers already present, set up channels immediately; also
  re-check `getPeers()` after a short delay. Records whether this page is host
  or guest.
- `leave()`: close channels, `roomObj.leave()`, clear the session. Called by the
  HTML Leave/reload path and `Socket_Finish`.
- `setupPeer(peerId, pc)`: create the two negotiated channels, attach
  `onopen`/`onmessage`/`onclose`, send hello on ctl open.
- ctl `onmessage`: type 2 appends bytes to `ctlQueue`; type 3 sets `eof`;
  type 4 sets `eof` + `closed`; type 1 validates role/version.
- listen state is readable when `pending.length > 0`. Peers that said hello
  before the host's engine reached `Socket_Listen` are already in `pending`,
  so no client is lost by host setup time.
- connect state is connected when the host peer's ctl opened and its hello
  arrived; failed on Trystero `onJoinError`, a 20 s timeout, or cancel. A host
  that is still in its setup menu counts as connected; the guest simply waits
  for the server config.
- `accept`: shift `pending`, bind the new fd to that peer.
- `send`: copy bytes out of the wasm heap before queueing.
- `recv`: copy from the queue into the wasm heap.
- `shutdownWrite`: send ctl type 3.
- `close`: the role-based rules above.
- Expose `stats()`, `status()` and `leave()` for the lobby and tests.

The engine's data volume is tiny (~400 B/s per client), so queues are simple
arrays. A 512 KB `bufferedAmount` threshold on ctl is enough backpressure.

### 8.6 Engine entry hooks

All guarded with `#ifdef __EMSCRIPTEN__` and a `/* web port: ... */` comment.
No netcode or game behaviour changes.

- `web/net_web.h` (new): declares `XBWeb_Mode()`, `XBWeb_RoomCode()`,
  `XBWeb_ClearIntent()`, `XBWeb_ReloadLobby()`, implemented in
  `web/net_web.c` with `EM_JS` reading `globalThis.xbConfig`.
- `menu.c: DoMenu`: on the first call only, read the intent. Host → set
  `gameType = atomServer` and call `CreateStartNetGameMenu(&gameType)`. Join →
  set `gameType = atomClient` and call `CreateJoinNetGameMenu(&gameType)`.
  Then clear the intent. Otherwise create the main menu as today. Later calls
  (after a match) show the main menu.
- `menu_game.c: ButtonStartServer`: after storing the game config, call
  `XBWeb_ServerListen(par)` instead of `CreateServerMenu(par)`. The level menu's
  default (`mlp.funcDefault`) points at `ButtonStartServer` on web, so choosing
  levels still starts listening.
- `menu_game.c: CreateJoinNetGameMenu`: on web, omit *Search Central* and
  *Search LAN*, keep the player/bot/music setup, and make *Connect* the default.
  Clear the unused menu ids so `PollStartGame` does not touch stale items.
- `menu_game.c: ButtonStartClient`: after storing the config, call
  `XBWeb_ClientConnect(par)` instead of `CreateClientMenu(par)`.
- `menu_network.c` / `menu_network.h`: add
  - `XBWeb_ServerListen(void *par)`: retrieve host defaults, set
    `cfgServer.name = room`, `port = 16168`, `game = room`, disable
    `fixedUdpPort`, `browseLan`, `allowNat`, `central`; store; call
    `Server_StartListen`; return `CreateServerWaitMenu` or a clear error. The
    room was already joined by the lobby; `Socket_Listen` only attaches.
  - `XBWeb_ClientConnect(void *par)`: set `cfgServer.name = room`,
    `port = 16168`; store IP/game host; call `Client_Connect`; on success
    return `CreateClientWaitMenu`, on failure show an error and return
    `CreateJoinNetGameMenu`.
- The engine's own network entry points are removed on web, so an obsolete
  plumbing screen cannot be reached from the main menu:
  - `menu.c: CreateMainMenu`: on web, drop *Create Network Game*, *Join Network
    Game* and *Start Central*; add a *Multiplayer Lobby* button that calls
    `XBWeb_ReloadLobby()` (reload to the HTML lobby). The menu becomes Solo,
    Multiplayer Lobby, Options, Quit.
  - `menu.c: CreateOptionsMenu`: on web, drop the *Central* entry.
  - `menu_network.c: ButtonServerDisconnect`: on web, after disconnecting
    clients, return to the main menu instead of *Setup Server*.
  - `menu_network.c: CreateServerMenu` and `CreateClientMenu`: on web, they are
    safety nets only; return to the main/join menu instead of rendering the
    obsolete hostname/port forms.
- `menu_network.c: CreateClientWaitMenu`: on web, replace the dead
  `Chat with lamer Rado ... http://xblast.sf.net/irc/` label with a room line,
  e.g. `Room <code> - waiting for the host to start`. The upstream string stays
  in the `#else` branch.

The host's *Start Network Game* menu and the guest's *Join Network Game* menu
remain the places where players choose local players, levels, bots and music.
The obsolete plumbing screens do not appear on web.

### 8.7 Lobby and status UI (`web/index.html`)

- Landing becomes two cards:
  - **Solo**: the existing Play button.
  - **Multiplayer**: room-code input (editable, generated default), a shuffle
    button, **Host** and **Join** buttons. One short line explains: share the
    code, the host starts the match, the guest joins and waits.
- Clicking Host/Join writes `globalThis.xbConfig = {mode, room}`, calls
  `XBNet.enter(mode, room)` (so the host is discoverable while it configures),
  hides the landing, shows a compact status bar, then loads the engine.
- The status bar is a small fixed chip, not a full-screen overlay, so engine
  menus and error dialogs stay visible. It shows:
  - role and room code, with a copy button;
  - a state dot: joining relays / waiting for the other player / connected /
    failed;
  - a **Leave** button that calls `XBNet.leave()` and reloads.
- While connecting, a non-modal toast shows "Connecting to room …" with
  **Cancel**. Cancel reaches the C connect loop and aborts the wait.
- After a match, the engine returns to its main menu; the status bar stays with
  **Leave** (reload) available, and the main menu's *Multiplayer Lobby* entry
  also reloads to the lobby. The lobby is not forced back over the engine.
- No new UI framework, no build step, same dark/yellow monospace style.

### 8.8 Errors

- Wrong room/no host: 20 s connect timeout counted from `Socket_Connect` →
  toast explains, engine shows its connection error, user can retry or leave.
  A host that is still in setup does not trigger this because its hello is
  already present.
- Host aborts before a match: guests are disconnected, their accepted streams
  close, and they see EOF. The host's room stays open until Leave/reload.
- Trystero `onJoinError` (usually no direct path, TURN needed): surfaced
  verbatim-ish in the toast; M2 does not attempt a relay.
- Peer leaves mid-match: ctl `close`/peer-leave sets EOF; the engine's existing
  disconnect handling runs.
- Host leaves: same for every guest.
- Relay outage: the status bar shows signalling offline; the host keeps
  waiting, the guest fails at timeout.
- After a match the room is still joined. M2 has no in-place rematch; Leave or
  *Multiplayer Lobby* reloads to a fresh lobby.

## 9. Walkthroughs

**Host.** Click Host → `xbConfig={host, room}` and `XBNet.enter('host', room)`
→ engine boots and opens *Start Network Game* → player/level setup → Continue
stores config and calls `XBWeb_ServerListen` → `Server_StartListen` →
`Socket_Listen` attaches the listen fd to the already-open room; any guest that
said hello during setup is already pending → wait menu. Status bar: room code,
waiting for players.

**Guest.** Click Join → `xbConfig={client, room}` and
`XBNet.enter('client', room)` → engine opens *Join Network Game* → player setup
→ Connect → `XBWeb_ClientConnect` → `Client_Connect` → `Socket_Connect` waits
for the host hello. Because the host joined at its own click, the hello is
normally already there even if the host is still configuring; the guest goes to
the wait screen and waits for the server config. Status bar: connected.

**Match start.** Host sees the guest in the wait menu, presses Start.
`Server_StopListen()` closes the listen fd only; the room and the accepted
streams stay. The host's stream sends the game config, player configs, level and
seed over `xb.ctl`; actions flow over `xb.act`. The guest blocks on the host's
frame as designed.

**Leave.** Guest quits → stream close → close that peer's channels → host sees
EOF → existing disconnect handling. The room is left only when the page's Leave
or *Multiplayer Lobby* action runs.

## 10. Testing and acceptance

Automated, two headless Chrome processes, separate profiles and remote-debugging
ports. Chrome needs `--disable-features=WebRtcHideLocalIpsWithMdns` for loopback
WebRTC in headless; this is a test-harness flag, not shipped behaviour.

This test needs internet access because Trystero's default Nostr relays are part
of the shipped path. It is a developer-run acceptance test, not a CI gate. It
waits up to 60 s for discovery, retries a timed-out join once, and skips with a
clear message when `XB_TEST_OFFLINE=1`. If CI later needs a deterministic
version, that is a separate local-relay task; M2 does not add a test-only
transport to the app.

`scripts/netplaytest.py`:

1. Build, start `python3 -m http.server -d web/dist 8123`.
2. Open page A; set room `m2-test-01`; click **Host**; wait for engine; dismiss
   intro; choose a local player in *Start Network Game*; press Continue.
3. Wait for the host wait menu. Open page B; same room; click **Join**; wait;
   dismiss intro; choose a local player in *Join Network Game*; press Connect.
   Because page A joined at Host-click, page B should connect even if page A is
   still in its setup menu. The test exercises that ordering at least once.
4. Wait until both pages report a peer; press Start on the host; dismiss level
   intros on both.
5. Send a few movement/bomb keys on both; capture screenshots.
6. Assert via `Runtime.evaluate`:
   - each page's `window.__xbnet.stats()` shows `peers >= 1`,
     `ctlTx > 0`, `ctlRx > 0`;
   - after the match runs, `actTx > 0` and `actRx > 0`;
   - both pages reach the playfield (not a menu).
7. Print the room, peer ids, counters and engine console errors.

Manual acceptance with two normal browsers: same room, one hosts, one joins, a
round starts, both see the other player and both can move/bomb.

Acceptance is the M2 definition of done: a round starts and both clients exchange
control and action traffic. Audio/visual parity, 6 players, chat and reconnect
are not M2.

- Host tab backgrounding can stall the match.

  is not a CI gate.

## 14. Calls made during the design review

- **Room ownership.** The room belongs to the page/session, not the listen
  socket. `Socket_Listen`/`Socket_Connect` attach, `Socket_Close` detaches, and
  only Leave/reload/`Socket_Finish` leave. This fixes the match-start
  `Server_StopListen()` and match-end `Client_Disconnect()` lifecycles.
- **Host joins at Host-click.** This makes the host discoverable while it
  configures, so a guest that reaches Connect does not time out just because
